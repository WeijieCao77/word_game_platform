# 踩过的坑与犯过的错

> 这份文档只有一个用途：**同一个错不许犯第二次**。
>
> 老板的原话是「把每次犯的错踩的坑都记录一下」。所以这里不写漂亮话，
> 每一条都按同一个格式：**现象 → 根因 → 代价 → 现在的防线 → 怎么自查**。
> 「现在的防线」那一栏如果写的是「只有这条纪律」，说明它还没被固化成代码，
> 属于**随时会复发**的那一类，要格外小心。
>
> 记的人是接手这个项目的 AI，犯错的人大部分也是它。写下来不是为了自责，
> 是因为这些错有共同的形状——**看清形状，才拦得住下一次**。

---

## 一、判据类：检查器自己在骗自己

这一类占了所有错误的一半以上，形状完全一样：
**判据比现实浅一层，于是「没检查到」被当成了「没问题」。**

### 1. 用关键词扫源码冒充「界面覆盖率」

- **现象**：报告说 11 个主界面做了 10 个，实际点进去全是空壳。
- **根因**：源码里出现「阵容」两个字太容易了；扫关键词量的是「提到没提到」，
  不是「做没做」。而且那个骗人的空壳里正好有「积分榜」三个字——**假页面反而让分数更好看**。
- **代价**：一整轮实测的结论是假的。
- **现在的防线**：界面体检必须真点进每一页看有没有东西（`scripts/screens-freemode.mjs`）。
- **自查**：任何「覆盖率」数字，先问一句「它是怎么数出来的？点进去了吗？」

### 2. 只看首屏就判「能玩」

- **现象**：老板打开作品，「你的名字」有标签、**没有输入框**，点「下一步」原地不动。
  而体检报的是「✓ 能玩」。
- **根因**：判据只问了「打不打得开」。**打得开 ≠ 玩得动。**
- **代价**：老板亲自撞了两次，平台一声不吭。
- **现在的防线**：`scripts/fix-game.mjs` 的 `boot()` 会数标签对不对得上能填的控件、
  把字段填上再点主按钮、点完页面一个字都没变就判卡住；
  注入脚本另查 `<label for=x>` 指向一个不存在的 id。
- **自查**：任何「能玩」的结论，问「它点了几下？点完页面变了吗？」

### 3. 走不到的地方，判成「通过」

- **现象**：日志写着「开局走了 1 步，还是没看到导航」，结论却是「✓ 玩得动」。
- **根因**：走查走不下去时直接 `break`，然后按「没发现问题」处理。
  **「没测到」被当成了「没问题」**——这是第 1、2 条的同一个病，只是更露骨。
- **代价**：老板那条「导航很多都点不了」，连着三次没被验证。
- **现在的防线**：走不到导航 = 判不通过；某一屏一个能点的元素都没有 = 当场记「走不下去了」。
- **自查**：看到「通过」，先确认**它到底测到了哪一步**。测不到就不许报通过。

### 4. 反过来：判据太窄，冤枉了作品

- **现象**：连报三轮「第 2 屏一个能点的东西都没有」，而 AI 说它给三张卡挂了 `onclick`。
- **根因**：选择器只认 `button / [role=button] / .btn`，
  作品用 `<div class="card" onclick=…>` 做的卡片在体检眼里等于不存在。
- **代价**：差点把「我看不见」当成「作品没做」——**误报比漏报还坏**。
- **现在的防线**：判据放宽到 `onclick / data-act / tabindex / .card / .option …`，
  并且在报「没得点」之前，先把那一屏上像是能点的元素全部打印出来。
- **自查**：报「没有 X」之前，先把「我看到了什么」打出来。空口说没有，不算数。

### 5. 在输出里猜关键词，而不是看退出码

- **现象**：界面体检明明说「找不到任何导航——只有一屏」，回炉却没被触发。
- **根因**：触发条件是在输出里找「硬伤/占位/报错」这几个词，那句话一个都不含。
- **现在的防线**：判定一律用退出码。
- **自查**：任何「根据输出里有没有某个词来决定下一步」的逻辑，都是这条的复发。

## 二、归因类：把账算错在谁头上

### 6. 把平台自己的重启，当成作品的 bug

- **现象**：线上那部 VAL MANAGER 报 `registerSetup is not defined`，判定「开局即死」。
- **根因**：把每次观测的时间和部署时间对一遍才发现——**报错只出现在容器重启的那几分钟**，
  作品的 `screens-setup.js` 502 拿不到，于是调用它的那一行自然是空的。作品本身没坏。
- **代价**：为此写了两层静态护栏，还差点派 AI 去修一个根本不存在的 bug。
- **现在的防线**：注入脚本把资源加载失败单独认出来，横幅说「有个文件没能加载出来，
  刷新一下多半就好……不是这部作品的问题」，**并且不上报**；它引发的连锁
  `xxx is not defined` 也不上报（`resourceFailed` 闸门，有测试钉住）。
- **自查**：看到线上报错，**先把时间戳和最近一次部署对一遍**。

### 7. 相信 AI 的自述，没有自己去验

- **现象**：AI 说「输入框渲染不出来是运行库 `WGP.el` 对 input 属性处理有偏差」，
  然后绕开库改用原生 DOM。
- **根因**：我信了。实际拿真浏览器把 `el` 造 input 的七种写法逐个验了一遍——
  文本框、带初值的、空初值的、滑块、标签、下拉、容器里的标签+输入框——**全部正常**。
  运行库没那个毛病。
- **代价**：差点为一个不存在的平台 bug 动手改运行库。
- **现在的防线**：守则里加了硬规矩「别把锅甩给运行库：要先给能复现的证据」；
  我这边的纪律是**任何「平台有 bug」的说法都要自己复现一遍才认**。
- **自查**：AI 说某个平台组件有问题时，有没有一段能跑的复现？没有就当它没说。

### 8. 把浏览器插件的噪音算在作品头上

- **现象**：一个**全新的空作品**顶上挂着血红的
  「这部作品有一个没被处理的异步错误：Failed to connect to MetaMask」。
- **根因**：兜底脚本把 `window.onerror` 收到的一切都算作品的。
- **代价**：作者以为平台坏了；垃圾还会进 `read_errors`，让 AI 去修不存在的 bug。
- **现在的防线**：`play-diagnostics.ts` 里的 `NOISE` 名单 + 扩展协议前缀过滤；
  未处理的 Promise 拒绝只记录、不弹横幅。
- **自查**：报错来源是不是这个作品的文件？不是就别记。

### 9. 把没有证据的推测，说成结论

- **现象**：我说过「pro 这一档工具调用更稳」。实测一跑：pro 单轮 12 分 44 秒撞上限、
  活没干完；flash 3 分钟完整交活并通过复验。**证据是反的。**
- **根因**：拿「贵的应该更好」当论据。
- **代价**：差点让老板为一个没验证的判断长期多付钱。
- **现在的防线**：只有纪律——**说出口的每一条结论，问自己「哪一次运行证明了它」**。
- **自查**：汇报里出现「更稳/更好/应该」这类词时，后面有没有跟一个具体数字。

## 三、流程类：自己把自己绊倒

### 10. 一边部署，一边跑实测

- **现象**：`让 AI 修一部作品` 两次红着退出，报「服务重启了，这一轮没跑完」。
- **根因**：我在实测跑着的时候合并 PR / 改 Railway 变量，两者都会触发重新部署，
  容器一重启就把跑到一半的那一轮打死。`CLAUDE.md` 里白纸黑字写着这条纪律，我破了两次。
- **代价**：两轮实测白跑，老板多等了二十多分钟。
- **现在的防线**：脚本认出「服务重启」类错误会等 60 秒自动重发一次（只重试一次）；
  但**纪律本身没有被代码强制**——派活之前必须确认没有部署在途。
- **自查**：动 Railway 变量 / 合并 PR 之前，先问「现在有实测在跑吗？」

### 11. 用 `cat >` 覆盖了一个已经存在的文件

- **现象**：新写的 `tests/runtime-errors.test.ts` 把同名的旧测试整份盖掉了
  （旧的测的是存储层规矩 + 运行库真的会报）。
- **根因**：写新文件之前没看目录里有没有重名的。
- **代价**：差一点把一整份护栏测试永久删掉（靠 `git` 里的历史捞回来了）。
- **现在的防线**：只有纪律——**新建文件前先 `ls`**，或者用 `git status` 复核。
- **自查**：`git show HEAD --stat` 里有没有本该是「新增」却显示成「修改」的文件。

### 12. 单轮失败就打死全场

- **现象**：某次实测第 1 轮撞了三次 502 就 `break`，14 轮一轮没跑。
- **根因**：服务端是「改一次存一次」的，那一轮的活其实做了，只是回信丢在网关上。
- **现在的防线**：连着三轮都失败才停。
- **自查**：任何「一次失败就整体放弃」的逻辑，先问「这一次失败真的意味着后面都没意义吗？」

### 13. 实测的半成品留在公开游戏库里

- **现象**：老板看到库里两部同名 VAL MANAGER，其中一部是死的。
- **现在的防线**：实测跑完把作品从公开库撤下来；后台有「撤下 / 删除」。
- **自查**：跑完实测，公开库里有没有多出来的东西。

## 四、平台机制类：平台自己看不见的东西

这一类不是「谁犯了错」，是**平台的设计缺口**——但每一个缺口都以「AI 说做好了、
实际是坏的」的形式砸在作者脸上，所以放在同一份文档里。

### 14. 草稿改了没发布，玩家还在跑旧代码

- **现象**：AI 修了两轮，冒烟检查报的还是一模一样的崩溃，
  第三轮它判定「这是旧记录、行号对不上」于是不改了。
- **根因**：作者看草稿、玩家看最近一次发布的快照。这条规矩对 AI 是隐形的。
- **现在的防线**：`src/lib/publish-drift.ts` 把落差写成一句话贴进上下文。

### 15. 提示里写着假话

- **现象**：自由模式一轮只长一千字符。
- **根因**：`prompt.ts` 里写着「一轮有时间上限（默认 40 秒）」，而实际有 12 分钟。
  模型照着那句假话把活切碎，每轮末尾交底问「要继续吗」。
- **代价**：一部一万三千行的作品这样永远搭不完。
- **现在的防线**：预算由 `buildSystemPrompt(config, mode, budgetMs)` 如实注入，有测试钉住。
- **自查**：守则里所有写死的数字，跟代码里的实际值对得上吗？

### 16. 作者预览里的报错，传不回平台

- **现象**：作者在预览里看到血红横幅，AI 调 `read_errors` 却是「没有报错记录」，
  于是坦然宣布做好了。
- **根因**：玩家页会把沙箱抛的异常送回服务端，**编辑器的预览页签一个字都没接**。
- **现在的防线**：外壳协议抽成 `src/components/game-frame.ts`，玩家页与预览共用同一份；
  报错自动贴进每轮的【运行报错】；编辑器当场弹「让 AI 去修」。

### 17. 「点了没反应」不抛异常，平台完全看不见（2026-08-27 已补上防线）

- **现象**：AI 连修 4 轮、发布 5 个版本，每轮都说「修完了」，
  实际开局第 2 步一个能点的元素都没有，玩家永远走不到主界面。
- **根因**：平台喂给 AI 的只有【运行报错】——**有异常才有记录**。
  一个渲染出来、但没人接点击的界面，在平台眼里干干净净。**AI 是瞎着干的。**
- **代价**：这是目前最贵的一条：老板三次投诉、四轮修复、二十多分钟，全卡在这里。
- **现在的防线**：`src/lib/playcheck/` 的试玩体检。平台开一个屏幕外的沙箱 iframe
  把作品从开局真点一遍（判据只有一条：点完界面变没变），结果存进服务端，
  下一轮自动出现在 AI 上下文的【试玩体检】里，作者也能在工作台的「体检」页签看到。
  守则里跟着写死一句：**没有【运行报错】≠ 没问题**。
- **还剩什么**：体检只查「走不走得通」。**好不好玩、数值对不对，它一个字都量不了**
  （见 `DESIGN-REVIEW.md` 第六条）。别拿「体检通过」当成作品做好了。

### 17.5 拿匿名浏览器去验一部**没发布**的作品，然后判它「坏了」

- **现象**：回炉三轮全废。每轮都报「✗ 玩不了　正文 13 字」，那 13 个字是
  `not published`——作品早先被我从公开库撤下了，`/play` 对非作者一律 403。
  而平台自己的试玩体检（带会话 cookie、看草稿）**第 1 轮之后就报了「试玩通过」**。
- **根因**：`fix-game.mjs` 的 `boot()` 开的是一个不带 cookie 的匿名浏览器。
  我在 PR 里写「boot() 带着会话 cookie，看到的本来就是草稿」——**那句话是错的**，
  我没去看那几行代码就写了。判据于是永远为假，AI 修得再对也过不了。
- **代价**：三轮 AI、十分钟、一次错误的「没修好」结论。
  而 AI 自己在第 2、3 轮已经把真相说出来了（「不是代码坏了，是草稿没发布」），
  是我的脚本在跟它较劲。
- **现在的防线**：`boot()` 默认带 cookie 验草稿；`asPlayer=true` 才开匿名浏览器，
  用在发布之后确认玩家侧。`not published` 单独认，不再算作「作品坏了」。
- **怎么自查**：**写进 PR 或汇报里的每一句「它是这样工作的」，先回去看那几行。**
  这条跟二类那几条是同一个毛病：凭印象归因。

### 17.6 「导航 0 项都能切」——一项都没测到，却写得像通过了

- **现象**：试玩体检的结论写「试玩通过（走了 8 步，导航 0 项都能切）」。
  0 项意味着**一项导航都没找到**，那一段根本没测到。
- **根因**：结论文案直接把 `nav.length` 填进「N 项都能切」的句子，没管 N 是不是 0。
- **代价**：还没造成事故，但这是第四次栽在同一件事上（判据浅 / 把「没测到」
  说成「没问题」）——前三次每一次都让老板的投诉漏了过去。
- **现在的防线**：`summarizePlayCheck` / `describePlayCheck` 在没找到导航时明说
  「没找到导航，那一段没测到，别当成通过」，并有测试钉住。
- **怎么自查**：报告里每一个数，先问「这个数是 0 的时候，这句话还成立吗」。

### 17.7 未发布的作品，归属人登录着也打不开——而报出来的是一句「跨域」

- **现象**：第二次回炉三轮又全废。每轮都是「有个文件没能加载出来（style.css）」，
  控制台一串 `blocked by CORS policy: No 'Access-Control-Allow-Origin' header`。
- **根因**：两层叠在一起。① `/p/:id` 只认地址栏里的 `?k=`，归属人凭登录态打开时
  **页面出得来**（同源、带 cookie），可 iframe 里的子请求全 403——沙箱是不透明源，
  它发的子请求算跨站，SameSite=Lax 的 cookie 一律不带
  （`/api/games/:id/preview` 的注释里早就写着这条，我没把它和这个场景联系起来）。
  ② 那个 403 响应**没带 ACAO**，于是浏览器把它变成一句「跨域被拦」——
  看的人（和 AI）会去查一个根本不存在的跨域配置问题，而真相只是「这作品没发布」。
- **代价**：三轮 AI。而且报错本身在**误导**排查方向，比不报还坏。
- **现在的防线**：`/p/:id` 在服务端就换好预览通行证（有会话且是归属人才换，
  通行证进路径，编辑钥匙不进 HTML）；`/play` 的 403 带上 `access-control-allow-origin: *`。
- **怎么自查**：**看到「跨域」先别信它。** 先问这个请求本来该是 200 还是 4xx——
  一个没带 ACAO 的 4xx，在跨域场景里一律长成「跨域问题」。

### 17.8 假绿：把中途那四个页签当成主导航，报「试玩通过」

- **现象**：体检报「试玩通过（走了 3 步，导航 4 项都能切）」，而同一时刻我的脚本
  报「开局走了 4 步，导航 11 项，其中 1 项有问题：总览点了没反应」。
- **根因**：挑东家那一屏有四个赛区页签——短标签、并排、不是流程按钮，
  于是 findNav() 认了它，走查当场收手。真正的 11 项主导航根本没走到。
- **代价**：**假绿比不报还坏**。上一条（17.6）刚把「没测到说成没问题」堵住，
  这一条换个形状又来一次：这回连「没测到」都不说，直接说通过。
- **现在的防线**：只有「像主导航」的才算数——挂在
  `<nav>` / `role=navigation` / `.nav|.tab|.menu` 里，或者足够长（>=6 项）。
  都不满足就当没找到，报「这一段没测到」。
- **怎么自查**：**每加一条「满足 X 就算通过」的判据，先问「什么东西会碰巧满足 X」。**
  短标签并排的东西在游戏界面里到处都是。

### 17.9 假绿第二形态：类名叫 region-tabs 的东西也被认成主导航

- **现象**：17.8 那条改完，线上又连着两次报「试玩通过（走了 3 步，导航 4 项都能切）」，
  而同一时刻脚本报「导航 11 项」。
- **根因**：17.8 加的判据是「挂在 nav/tab/menu 类名里 **或** 够长（>=6 项）」。
  挑东家那一屏的赛区页签容器类名带 tabs，navish() 认了它，四项就够，走查当场收手。
  **判据放宽的那一半，把收紧的那一半抵消掉了。**
- **代价**：又两次假绿。同一个毛病改了两遍才堵住。
- **现在的防线**：把「够不够格让我停下来」和「停下来之后扫哪一组」**分开**——
  收手门槛硬性 >=6 项（不看类名），扫哪一组仍按 navish 或 >=6。
  真有 4 项主导航的作品照样扫得到，只是不会因为它提前收手。
- **怎么自查**：**加「或」的时候要问：这个「或」会不会把刚加的那道闸门绕过去。**

### 17.10 注释里的反引号把模板字符串提前闭掉

- **现象**：给 sweep.ts 加注释，`tsc` 报 `TS1005: ',' expected`。
- **根因**：那段注释在一个 TS **模板字符串**里面（注入浏览器的脚本是拼字符串拼出来的），
  注释里写了一对反引号，直接把模板字符串闭掉了。同一天在 prompt.ts 上栽过一次。
- **代价**：一次编译失败，几分钟。
- **现在的防线**：只有纪律。往模板字符串里写中文注释时不要用反引号，用「」或直接不加。
- **怎么自查**：改一个 .ts 文件里的**字符串常量**之前，先看清自己在不在反引号里面。

### 17.11 假绿第三形态：走满 14 步都没走到主界面，报「试玩通过」

- **现象**：`play_check` 端到端实测那一轮，同一分钟里两个检查器给了相反的结论——
  平台的走查报「试玩通过（走了 12 步，导航 4 项都能切）」，
  `fix-game.mjs` 的 `boot()` 报「开局第 4 步点下去，页面一个字都没变——走不下去了」。
- **根因**：17.9 把「收手门槛」提到 6 项之后，走查不再提前收手了——它改成一路点到步数用光。
  可是**「走完了」和「走到了」这两件事，报告里根本分不出来**：
  走满 `MAX_STEPS` 退出时 `stuck` 是 null、路上没有坏按钮、`nav` 里是挑东家那一屏的
  四个赛区页签，于是 `playCheckHasIssue()` 一条都不命中，一句话结论直接写「试玩通过」。
  **上一条只堵住了「提前收手」，没堵住「压根没走到」。**
- **附带**：那句「走了 12 步」也是假的。`steps` 存的时候截到 12 条，
  真实走了 14 步——**拿一个被截断的数组去数步数**。
- **代价**：AI 当轮拿到「试玩通过」就收工，这一轮白费。假绿第三次换形状出现。
- **现在的防线**：走查显式记 `arrived`（是不是**因为认出主导航**才收手）和 `walked`
  （真实步数，不受截断影响）；`arrived` 为假一律算查出问题，措辞是
  「体检点了 N 步，**始终没走到有导航栏的主界面**」，并留一句
  「本来就没有导航栏（纯线性故事）就忽略」让 AI 能自辩。
  老报告缺这个字段时一律按 `false` 算——宁可误报，不许假绿。
- **怎么自查**：**一个循环有几种退出方式，报告里就得分得出是哪一种。**
  「没卡住」不等于「走到了」；`break` 和「跑满」写在同一个 `for` 里，
  出来以后一定要有个东西记着是哪一条路出来的。

### 17.12 「一步最多试 10 个」名存实亡——重画之后那张候选名单全过期了

- **现象**：两个走查器对账，平台走查 3/3 次走满 14 步没走到主界面（导航只扫到
  挑东家那一屏的 4 个赛区页签），而 `fix-game.mjs` 的 `boot()` 5 步就进了 11 项主导航。
  **平台自己那只眼睛才是瞎的那个**，跟我事先的判断正好相反。
- **根因**：走查一步之内的重试是这么写的——先 `clickables()` 采一张候选名单，
  然后 `for` 着这张名单挨个点，`if (!document.contains(el)) continue;`。
  可作品都是「innerHTML 整片重画」，**点完第一下，名单上剩下的元素全部脱离文档**，
  于是一个不落地被 `continue` 跳掉。写着「一步最多试 10 个」，
  实际**每一步只试得成一个**——跟当场放弃没有区别。
- **代价**：平台的第三只眼在真作品上基本没用；线上那部作品被它报了三次
  「走了 14 步没走到主界面」，而它其实 5 步就能进主界面。
- **现在的防线**：每试一次都**重新采集**候选，按**名字**（不是元素）记这一步试过谁——
  重画之后元素是新的，名字还是那个。另加一条：点了会变、但变回一个**看过的屏**，
  算打转不算前进，这个标签沉到候选队尾（四个赛区页签就是这么把步数耗光的）。
- **新增的防线（更要紧的一条）**：`scripts/playcheck-selftest.mjs`——
  拿一份**我们自己写的、已知能走通**的假作品（整片重画 + 打转页签 + 11 项主导航）
  跑一遍走查，走不通就是走查坏了。它在修之前那一版上会失败，修之后通过。
  **体检器自己没有体检，就是这么瞎了三次都没人发现的。**
- **怎么自查**：**写「重试 N 次」的时候，先问第 1 次的副作用会不会让第 2 次失效。**
  在会重画 DOM 的页面上，任何跨点击持有的元素引用都是过期的。

### 17.13 「点了没反应」的假阳性：玩家点自己已经在的那个页签，本来就没反应

- **现象**：本地把平台整个跑起来、拿一份**自己写的、已知能走通**的假作品过一遍，
  走查报「开局路上 2 个按钮点了没反应：Americas、Pacific」。可那份作品是我写的，
  这两个按钮好得很。
- **根因**：走查一进挑东家那一屏，当前就在 Americas 赛区。它点了一下「Americas」——
  界面当然一个字不变，于是记成「点了没反应」。再走两步它点「Americas」切回来时
  界面明明变了，可那条记录已经写下了。**导航扫描早就有 already 这个概念
  （「已经在这一页了」不算坏），开局走查这一段却没有。**
- **代价**：这不是纸面上的。线上那一轮 AI 就是照着「Americas 点了没反应」去改的，
  把「点已选中的页签」改成强制重绘——**为了迁就一份错报告，改了本来没问题的代码**。
  一轮就这么花掉了。
- **现在的防线**：记下哪些标签**后来被证明好使**，收尾时把它们从坏按钮名单里划掉。
  「点了没反应」只有在这个按钮**从头到尾都没反应**的时候才算数。
  自检里也钉了一条：那份假作品报出任何一个坏按钮都算走查有问题。
- **怎么自查**：**报「X 坏了」之前，先问「X 在什么正常情况下也会这样」。**
  这跟 17.8 是同一句话的两面：那次问的是「什么东西会碰巧满足我的通过判据」，
  这次要问的是「什么正常行为会碰巧满足我的失败判据」。**两头都要问。**

### 17.14 同一个假阳性换个地方又来一次：主界面默认停在第一项

- **现象**：三个毛病修完，线上对账 3/3 次报「走 13 步 · **到主界面** · 导航 11 项 ·
  **点不动[总览]**」。走查终于走到主界面了（修之前是 3/3 走 14 步进不去），
  可它报的那一项是冤枉的。
- **根因**：作品一进主界面**默认就停在第一项**（总览高亮、总览的内容已经铺好）。
  走查扫到第一项时点下去，界面当然一个字不变。导航扫描本来有 `already` 这个概念
  （「已经在这一页了」不算坏），但它只认得出**体检自己先点开过**的那一种——
  作品**自带的默认落点**它认不出来。
  **这跟 17.13 是同一个假阳性，只是从开局走查换到了导航扫描那一段。**
- **代价**：又一次「让 AI 去修一个没坏的东西」。17.13 那次已经花掉过一轮了。
- **现在的防线**：扫完一圈之后**回头再点一次**那些「看着点不动」的——
  一圈下来当前停在最后一项，这时候再点它就问得出真假。
  **只有从别处点它也不动，才算真的点不动**（跟开局走查那边的判据对齐了）。
- **顺手补上的更要紧的一条**：自检从「一份好作品」改成**两份**——
  一份一个毛病都没有（报出任何问题都算走查有毛病），一份**有且只有一个坏导航项**
  （必须不多不少正好逮到那一项）。因为治假阳性很容易治过头：
  判据一放宽，真坏的那一项也跟着被放走，平台就从「冤枉好人」变成「放走坏人」，更糟。
  修之前那一版跑这套双向自检：好作品多报「总览」，坏作品报「总览、赛程」，两头都红。
- **怎么自查**：**同一类判据错误，在别的地方大概率还有一份。** 修完一处，
  先去找它的兄弟——「已经在这一页了」这个概念，开局走查和导航扫描各需要一份，
  而且两边的判据要对齐。

### 17.15 `⚠ terminated` —— 一个词的报错，因为 cause 在第一步就被扔了

- **现象**：作者在工作台发了一句「把采信簿从推理结论改成物理陈述」，等了一会儿，
  对话里冒出来一行 **`⚠ terminated`**。就这一个词。没有原因、没有下一步，
  也不知道那一轮是不是白花了（底下写着「管理员·不限量」，跟额度无关）。
- **根因（三处叠在一起）**：
  1. `terminated` 是 **Node 的 fetch（undici）** 抛的原话——上游把流从中间掐断时，
     它抛 `TypeError: terminated`，`message` 字面上只有这一个词，
     **真正的原因在 `err.cause` 里**（`other side closed` / `ECONNRESET`…）。
  2. 调用方写的是 `err instanceof Error ? err.message : String(err)`——
     **cause 整个丢了**。全仓库 grep `cause`，一处相关的都没有。
  3. `explainAiFailure` 有一条专管网络的分支（timeout / etimedout / fetch failed /
     socket），**`terminated` 一个都不匹配**，于是掉到最后一行 `return detail`，
     把那个孤零零的词原样吐给作者。
- **代价**：那一轮真丢了（服务端任务内部挂的，客户端那套「先别重发」的捞回机制
  只管客户端断线），token 白烧，而作者拿着一个 `terminated` 什么也做不了。
- **现在的防线**：
  - `errorDetail()` **摊平 cause 链**（连 `code` 一起），
    错误从「terminated」变成「terminated（起因：other side closed / UND_ERR_SOCKET）」。
  - `explainAiFailure` 认得出这一类，并且**排在「超时」那条前面**——两类要说的话不一样：
    断线要回答的是「半份文件丢没丢、要不要重发」，超时那条一个字都没答。
  - 两个函数从路由里的私有函数挪成独立模块，**这才第一次测得到**。
  - 顺手补了一个**空闲**看门狗（不是总时长——按总时长掐会掐死正常的长生成）：
    连着 3 分钟一个字节都不来就判定断线，不再挂满 12 分钟的轮次预算。
- **写看门狗时又踩一个**：`reader.cancel()` 会让挂着的 `read()` 以 `{done:true}` 结束，
  `Promise.race` 谁先落谁赢——**先 cancel 再 reject，流就被判成「正常读完了」**，
  半份回复当成功返回。必须先 reject 再 cancel。自测里就是这么抓到的。
- **怎么自查**：**报错信息只取 `message` 是不够的。** 有一整类错误
  （undici 的网络错、`AggregateError`、包过一层的库错）把真相放在 `cause` 上；
  只取 message 等于把故障原因扔了，然后对着一个词猜半天。

### 17.16 `as PlayCheckReport` 不是校验——库里躺着的是三个版本前的形状

- **现象**：昨天那一版上线之后，作者在工作台发一句话，回来一行
  **`Cannot read properties of undefined (reading 'nan')`**。整轮对话当场断掉。
- **根因**：`playCheckGet()` 写的是

  ```ts
  return JSON.parse(row.report) as PlayCheckReport;
  ```

  **一个裸的类型断言，不做任何整形。** 而我前一天刚给报告加了 `numbers` 这一段
  （再前一天加的 `walked` / `arrived`）。库里躺着的报告是**加之前存下的**，
  没有那几个字段，于是 `r.numbers.nan` 当场炸。
  五个调用点全中：发布门槛、体检接口、AI 那一轮的三处。
- **我本来写过一条测试**：「老报告没有 numbers 这一段也不能炸」——**可它走的是
  `parsePlayCheck`，而从库里读根本不走那条路**。测了另一条路，还因此觉得自己防住了。
  **假的信心比没有信心更坏。**
- **现在的防线**：加 `revivePlayCheck()`，从库里读一律过一遍整形；
  跟收浏览器数据那个 `parsePlayCheck` 只差一件事——**保留原来的时间戳**
  （读一次盖一次章的话，发布门槛那条「体检比文件旧就拦住」就永远不会触发了，
  任何旧报告都会看起来像刚跑完的）。
  测试改成**把旧形状真的写进库里再读回来**，并且在线上那一版上验过：
  确实抛出一模一样的 `Cannot read properties of undefined (reading 'nan')`。
- **怎么自查**：**类型断言不是校验。** 凡是从库里、从网络、从别的进程回来的东西，
  类型系统给的保证全是假的——写它的可能是三个版本之前的自己。
  加一个字段之前先问：**已经存在库里的那些行，读回来会怎样？**
  还有一条同样要紧：**测试必须走真实那条路**。测了旁边那条，等于没测。

## 五、环境类：这个容器和这条部署链

### 18. 容器会「回退」

远程容器闲置会被回收，重建后文件系统回到一个较旧的快照，**只存在于容器里的东西会整批消失**。
已经 push 到 GitHub 的一点不少。→ **每完成一段就 commit + push**。

### 19. 出口屏蔽

容器够不到 `railway.app` 与 `api.github.com`。Railway 操作走 GitHub Actions，
GitHub 操作走 MCP 工具。**任何「我直接 curl 一下线上」的念头都行不通。**

### 20. `railway redeploy` 不会拉新代码

它只是把同一个 commit 再部署一遍。改环境变量能立刻生效，改代码必须重新部署。
反过来说这也是应急手段：能用变量控制的东西，改变量最快。

### 21. 体检脚本跑在 runner 上，不需要部署

`scripts/*.mjs` 是在 GitHub 的机器上通过网络驱动线上的，
**改检查器改完就能用**；只有平台本体（守则、注入脚本、API）才要重新部署。
我一度为此白等了好几轮部署。

## 六、自查清单（每次汇报前过一遍）

1. 我说的「通过 / 能玩 / 修好了」，**测到哪一步为止**？测不到的部分说清楚了吗？
2. 我报的「没有 X」，把「我看到了什么」打出来了吗？
3. 我把这次失败**归因给谁**了？时间戳跟部署对过吗？是不是插件/网络/重启？
4. AI 说的话，我**自己验过**吗？
5. 结论里的「更好/更稳/应该」，后面跟着数字吗？
6. 我现在要动的东西，会不会**打断正在跑的实测**？
7. 新建的文件，目录里**有没有重名的**？
8. 干完这一段，**commit + push 了吗**？
