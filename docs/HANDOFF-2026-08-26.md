## 一、这段时间在干一件什么事

老板的验收标准只有一条，而且反复确认过三次，三句话缺一不可：

1. **量的是玩家的体验，不是代码**。题材名字可以是我们自己的，玩家看不到代码
2. **深度和丰富度一分不能少**：518 人的规模、按天推进、地图 ban/pick、逐回合直播、
   26 个界面、没有结局的开放式生涯。规模本身就是体验的一部分
3. **必须由平台的 AI 做出来**。接手的人**一行游戏代码都不许自己写**，
   每个文件都得是线上 AI 通过 `/api/games/:id/assistant` 写进去的。
   手搓一份塞进去，测的就不是平台了。我们的活是**修平台**，直到它的 AI 做得出来

## 二、怎么量：`valmanager-e2e` 流水线

`.github/workflows/valmanager-e2e.yml`，手动触发（`rounds` 建造轮数、`fix_rounds` 回炉轮数）。

一次跑完做这些事：

1. **等部署跟上**——线上 `/api/health` 的 commit 要对上这次的 sha，否则不测
2. 建一个自由模式作品，**把 78 队 / 518 人 / 5 名分析师传进 `data/`**
   （`templates/valmanager/data/*.csv`，从原作 `src/data/world.json` 转的）
3. 第一轮发 `templates/valmanager/spec.md`（体验说明书），之后按十步驱动，
   每轮打印**增长曲线**（文件数 / 总字符 / 这轮 +多少）与额度
4. 关键词覆盖率——**只是参考，不要当结论**（见第四节）
5. **真玩一遍**（`scripts/smoke-freemode.mjs`）：打得开 / 有得点 / 点得动 / 存档 / 手机不溢出
6. **界面体检**（`scripts/screens-freemode.mjs`）：把导航一个个点过去，
   每页记字数、可点元素、表格行数、报错；**「建造中」空壳一律判红**
7. **把玩出来的问题喂回去让 AI 自己修**，修完再玩，最多回炉 N 轮
8. 从公开游戏库撤下来（别往库里堆垃圾）
9. 硬门槛：冒烟检查与界面体检两个退出码都得是 0

**workflow 只上传 `data/*.csv`，代码文件一个都不传**——那是 AI 的活。

## 四、几条血泪教训（别再踩）

- **关键词扫源码的覆盖率会骗人**。源码里出现「阵容」两个字太容易了。
  真正算数的是界面体检——点进每一页看有没有东西
- **「建造中」占位页比空页面更坏**。已经在技能包与说明书里写成铁律：
  没做的页面不许挂进导航；界面体检见到就判红
- **单轮失败不能打死全场**。服务端是「改一次存一次」的，那一轮的活其实做了，
  只是回信丢在网关上——跳过接着走才对
- **单轮预算不能超过网关的耐心**。曾经放宽到 420 秒，结果最重的那一轮必然 502。
  现在 240 秒（`AI_ROUND_BUDGET_CODE_MS`），靠多轮而不是长轮
- **判定用退出码，别在输出里猜关键词**。第 2 次就是这么放过去的
- **实测跑完要把作品撤下来**，别往公开库里堆半成品

## 五、这一轮补进平台的能力（都是被实测逼出来的）

| 模块 | 解决什么 |
| --- | --- |
| `public/wgp/runtime.js` + `style.css` | 自由模式的地基：存档桥、界面路由、表格/进度条/弹层、打字机、**可复现随机数**。平台在 `/play/:id/` 下虚拟出来，作品不必自带 |
| `src/lib/dataset.ts` | 数据表：`data/roster.csv` → 虚拟 `data/roster.js` → `WGP.data("roster")`。沙箱 `connect-src 'none'` 读不到 csv，这是唯一走得通的路 |
| `src/lib/ai/file-view.ts` | **文件再大都改得动**：大文件 `read_file` 给目录（每节在第几行），`from/lines` 取某段，`find` 搜原文。原来是「前三万字符截断」，作品长过三万字就卡死 |
| `src/lib/ai/inline-tools.ts` | 模型把工具调用当正文吐出来时捞回来。实测里这样白白烧掉过两轮 |
| `game_errors` + `read_errors` 工具 | **自由模式版的校验器**：运行库在沙箱里抓异常 → 外壳送回服务端 → AI 读得到。以前 AI 写完就交差，永远不知道自己的游戏炸了 |
| `game_versions` + `live_version` | **草稿与线上分开**：作者改草稿，玩家看最近一次发布的快照，坏了能回滚 |
| `/api/admin/games` + `/admin` 的「公开游戏库」 | 平台主人终于能把作品从公开库撤下来（**只撤不删**） |
| `/new` 先选路再选起点 | 自由模式原来藏在 11 个模板的第 4 行，老板自己都没找到 |

## 七、环境上的坑（一定会遇到）

- **容器会回退到旧快照**。今天发生了三次，每次都把没推的活吃掉。
  **每个回合开头先 `git fetch origin <branch> && git reset --hard origin/<branch>`**，
  写完一段立刻 commit + push，别攒着
- **出口屏蔽了 `railway.app` 与 `api.github.com`**。Railway 操作走 workflow，
  GitHub 操作走 MCP 工具。**从容器里 curl 线上是不通的**，别浪费时间
- **两条部署路子**：Railway 的 GitHub 集成（带 git sha）与 Actions 里的 `railway up`
  （不带）。所以 CI 会把 sha 写进 `public/build.json`，健康检查两条路都报得出来
- **每次推送都会触发重新部署**。实测跑着的时候推，会把那一轮压掉——
  要么等它跑完，要么接受一轮的损失（harness 现在扛得住）
- **定时自检已经取消**，现在没有任何 Routine 挂着。实测跑一次要一小时上下，
  期间需要有人回来看结果——要么自己盯着，要么再建一个绑到当前会话的每小时自检
  （内容照第二、三、四节写：查 run 状态 → 拉日志盯那几个数 → 卡点写进
  `docs/valmanager-gap.md` → 能修的当场修 → 再触发一次）
