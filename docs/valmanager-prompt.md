# 复刻实验：用平台做一款 VCT 电竞经理

这份文档记录一次**平台能力验证**：拿旗舰作品 VAL MANAGER（13k 行手写引擎、78 支战队、
518 名选手）当标尺，把它的机制拆成「创作者能说出口的话」，再用平台自己的 schema +
工作流做一遍，看做得出什么、做不出什么。

结论写在 `docs/valmanager-verdict.md`。

---

## 一、创作者会怎么说（可以直接粘进工作台）

> 我想做一款无畏契约（Valorant）的电竞经理游戏，玩家是一支职业战队的经理。
>
> **核心循环**：一个赛季分成若干周，每周我有几个行动点，可以拿去训练队员、
> 谈转会、跑商业活动、跟队员谈心。周末打一场联赛，赢了拿积分。
> 赛季末看名次，进季后赛才有机会夺冠。打完三个赛季游戏结束。
>
> **选手**要有细分属性，不是一个总评分——枪法、反应、意识、道具、残局、协同、
> 沟通、指挥，八项。每个人有位置（决斗者、先锋、控场、哨卫、自由人），
> 首发五人的位置得配齐，配不齐要掉战力。
>
> **训练**：每周给某个队员指定专项练一项属性，但练了会掉体能；体能低了状态会差，
> 甚至受伤。年轻人（21 岁以下）自己也会涨，老将（26 岁以上）会退步。
>
> **转会**：转会窗只在赛季前几周开。看得到别人队的选手和身价，钱够就能签；
> 也能把自己队的人挂牌卖掉换钱，但队友会不高兴。
>
> **商业**：接商业活动能赚钱但占用队员时间、掉士气；谈赞助要看声望，谈成了每周有进账。
>
> **董事会**：每个赛季开头会给我一个目标（比如「进季后赛」）。没完成一次会警告，
> 连着两次没完成就下课。
>
> **比赛**要有交代——不能只告诉我赢了输了，得让我知道为什么赢、为什么输：
> 谁打得好、哪一项吃了亏。
>
> 难度：标准。一局 20 分钟左右。结局要分层，不能所有人最后都看到同一段话。

## 二、这份 prompt 里每一条对应平台的什么能力

| 创作者的话 | 平台怎么实现 | 能不能做 |
| --- | --- | --- |
| 一赛季分若干周、每周几个行动点 | `driver.kind = "sim"` + `time.turnsPerCycle` + `driver.actionPoints` | ✅ |
| 周末打一场，赢了拿积分 | `settlements` + `leagues`（活积分榜） | ✅ |
| 八项细分属性 | `entityTypes[].attributes`（上限 30 项） | ✅ |
| 位置配齐才不掉战力 | `derived` 里用 `count("选手","控场")` 做系数 | ✅ |
| 指定队员练某项 | `actions` 带 `target`（实体作用域决策） | ✅ |
| 练了掉体能、体能低会伤 | 决策 effects + `curves`（每周消耗）+ 条件事件卡 | ✅ |
| 年轻人涨、老将退 | `curves` 按周期跑、条件写 `self.年龄` | ✅ |
| 转会窗只在前几周 | 决策 `condition: "turn <= 4"` | ✅ |
| 签人/卖人改变阵容 | 决策的 `add_tag` / `remove_tag` | ✅ |
| 商业活动赚钱掉士气 | 决策 effects | ✅ |
| 赞助按声望谈、谈成每周进账 | `chance()` + `settlements` 周结 | ✅ |
| 董事会目标、警告、下课 | 计数变量 + 条件结局 | ✅ |
| 比赛要交代为什么 | `settlements.compute` 中间量 + 「为什么是这个结果」面板 | ✅ |
| 结局分层 | 多个条件结局 | ✅ |
| **两两队友羁绊** | — | ❌ 见 verdict |
| **BO3/BO5 逐回合、地图 ban/pick** | — | ❌ 见 verdict |
| **季后赛淘汰赛对阵表** | — | ❌ 见 verdict |
| **多轮转会谈判（报价/还价）** | — | ❌ 见 verdict |
| **经理跨俱乐部生涯** | — | ❌ 见 verdict |
| **518 名选手全量模拟** | `entities` 上限 200 | ⚠️ 降级 |
