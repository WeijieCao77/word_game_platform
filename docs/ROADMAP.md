# 未来方向（Roadmap）

> 排序原则：**先把"任何人拿着工作台都能做出一款完整游戏"这件事做扎实**，再谈开放与规模。
> 每一条都写清楚"为什么要做"，接手的人可以据此重新排序，但不要在没想清楚"为什么"时先动手。

---

## 下一批候选（已有明确设计，随时可开工）

### 0. 快速 ⇄ 自由模式带进度切换（老板拍板要的，见 `PLATFORM.md` 第三节）
现状：快速 → 自由有「点头才能切」的闸门但等于推倒重来（只有设计卡和聊天记录还在）；
自由 → 快速完全没有。**做法**：切换时把设计卡、数据表（`data/*.csv`）、题材与人设设定
原样带过去，能翻译的内容尽量翻译（卡片文案 ⇄ 页面文案），切换前给创作者一张
「带得走什么 / 带不走什么」的清单确认。
**价值**：两条路并行的前提是创作者选错了路不用付出重做的代价——拿不准就先选快速模式
这句承诺，只有切换无损时才真的成立。

### 1. 分步可介入结算（MatchLive 式）
现在的结算是一次算完、给结果和复盘。Val Manager 的体验差距主要在这：比赛分回合推进，
中途允许玩家做决策（暂停、换人、改战术），每一步都看得见影响。
**做法**：`SettlementDef` 增加 `steps`（分步定义）与 `interrupt`（可介入点），
引擎在结算中途返回 pending 状态交给玩家，播放器渲染成逐步推进的面板。
**价值**：经营类从"看结果"变成"打一场"，这是 sim 品类留存的关键。

### 2. Digest 回合摘要
每回合结束给一段人话总结（这周发生了什么、数值往哪走、下周该注意什么），
而不是让玩家自己从日志里拼。**做法**：`config.digest` 定义模板与取数表达式，引擎在 endTurn 时生成。
**价值**：长线经营游戏的可读性，与结算复盘互补（复盘回答"为什么"，摘要回答"发生了什么"）。

### 3. 聊天框上传图片（带成本分流的设计）
作者在对话里直接传图。**关键是分两条通道，否则 token 会失控**：
- **素材通道（默认）**：图片只入库当游戏素材，AI 只收到一行文字元信息（文件名、尺寸），
  **不进模型上下文**，成本≈0。这覆盖绝大多数场景（立绘、场景图、UI 参考件）。
- **看图通道（显式勾选"请团队看这张图"）**：这一轮才把图片送进视觉模型，
  并让 AI 立刻用一段文字把图片内容写进设计卡；后续轮次引用那段文字，**不再重复送图**。
  另外这一轮临时切到支持视觉的 provider（DeepSeek 的文本模型不吃图）。
**价值**：作者能用参考图表达"我要这种感觉"，而平台不用为此付出每轮重复计费的代价。

## 中期

- ~~账号系统~~ **已完成**（自建，账号密码存平台自己的库）。当时评估过托管认证（Supabase/Clerk），
  最终按老板要求自建——密码用 scrypt 加盐哈希、会话只存指纹、登录限频。
  还没做的相关项：找回密码（需要邮件服务）、改密与改名、第三方登录、作者主页。
- **创作者数据后台**：`game_stats_daily` 已经按日落表，地基有了。缺的是给作者看的趋势图、
  结局分布漏斗（哪个结局没人走到）、流失点（玩家在第几张卡关掉的）。
- **sim 阶段进度模块**：换地图/换赛段时切换独立的对手池、事件池、招募池。
- **实体运行时生成**：无限青训、天骄池——现在实体是配置里写死的。
- **表现层主题扩展**：现在三套预设（paper/dark/terminal），作者应该能调出更像"自己作品"的样子。

## 校验器/引擎的已知窟窿（整改《他不是自己掉下去的》时撞出来的）

按修起来的性价比排序，都是小改动、影响面窄，但每一条都能让作者少踩一次坑：

1. **输入门答案漏写 `goto` 会静默掉进兜底结局**。story 调度器下，`submitInput` 命中的
   答案如果既没有 `goto` 也没有 `ending`，直接走 `timeoutEnding`——玩家答对了反而被结束游戏。
   作者完全看不出哪里错了。校验器该拦：story 调度器下的答案必须有去向。
2. **没有 `searched()` 表达式函数**。现在没有任何办法把内容门槛在「玩家用过检索台」上，
   所以检索永远只能是加分项，做不成硬性必需——而这恰恰是推理类最想要的（「你没查过这个词，
   就不该知道这件事」）。加一个白名单函数即可，档案/卡片/结局条件都能用。
3. **`simulate` 的输入门策略会放大重复率**。答案键全部试完后，随机策略会把每个键再挨个提交
   一遍，一次登门刷出六七行一模一样的「无匹配词条」。这会让 `verbatimRepeatRatio` 虚高，
   作者以为是自己文案的问题。
4. **`街口` 这类枢纽卡的选项已经顶到 schema 上限**（`choices` 最多 8 个）。想再加地点只能
   先拆走一个。要么放宽上限，要么给「地点导航」一个专门的表达方式（现在是拿选项硬凑的）。
5. **重复率的地板在导航行**。`simulate` 把选项按钮文字也算作段落，一局 33 次巷口就是
   33 行正文 + 33 行菜单。枢纽型作品靠 textVariants 只能压到 24% 左右，再往下要改结构。
   要么给导航类选项在统计上单独归类，要么把告警阈值按作品形态分档。

## 长期 / 需要先想清楚的

- **开放 API**（老板明确说"先把平台做好再考虑接口"）：让第三方 AI 把生成的图、
  爬取整理的数据传进某个游戏。要先解决：鉴权（比 editKey 更正经的东西）、配额、内容审核。
- **沙箱脚本层**：硬核作者的逃生舱，Web Worker 里跑自定义结算。**只有在受限表达式确实不够用时才做**，
  它会让"不写代码"的承诺出现裂缝。
- **运行时 AI**：游戏内动态生成事件卡（卡池结构已留接口）。成本与可控性都要先算清楚。
- **合规硬墙**：备案、许可证、内容审核、实名防沉迷——放量或收费之前必须处理，
  当前"境外域名 + 不收费 + 邀请制内测"阶段全部延后（详见 `HANDOFF.md` 第五节）。

## 明确不做

- **不把 Val Manager 迁进平台**：它是约 7000 行手写引擎的独立作品，作为旗舰内容与流量锚点存在。
  平台要做的是"让别人用工作台也能做出这个量级的游戏"，而不是把它搬进来。
- **不做音乐/音效设计岗**：平台定位是大量文字 + 少量图片的网页文字游戏。
- **不给所有游戏套统一模板**：见 `STATUS.md` 的第二条铁律。

## 怎么判断一个新想法该不该做

老板反复强调过的判据，接手时照着问：

1. **它是"平台能力"还是"某个游戏的需求"？** 平台要的是"用户有这个想法时做得出来"，
   而不是把现有游戏都改成那样。答案是后者就先别做。
2. **作者能不能只靠对话把它用起来？** 需要作者理解 schema 才能用的功能，等于没做。
3. **它是可选模块吗？** 检索台、档案夹、行动点、活联赛都是可选的——AI 觉得需要会建议，
   作者要就装。任何"每个游戏都必须有"的东西都要非常谨慎。
4. **过得了三级校验和 600 局模拟吗？** 过不了就不是完整的游戏能力。

## 附：做成"专业平台"要花多少钱

问题：现在是免注册 + SQLite + 单机部署，要做成 Lovable 那种正经产品（账号密码、正经数据库、
安全与合规），成本是多少？下面是分档估算（价格为 2026 年初的公开定价量级，落地前以各家官网为准）。

**先说结论：基础设施很便宜，真正的成本是 AI 推理，通常占总成本的 70%~90%。**
省服务器省不出什么，省 token 才是杠杆。

### 档位 A：内测期（现在，几十到几百用户）

| 项 | 方案 | 月成本 |
| --- | --- | --- |
| 托管 | Railway | $5~20 |
| 数据库 | SQLite on Volume（现状） | $0 |
| 账号 | 免注册 + 编辑钥匙（现状） | $0 |
| CDN/防护 | Cloudflare 免费档 | $0 |
| AI | DeepSeek 级模型 | $20~50 |
| **合计** | | **约 $30~80/月** |

这一档基本不用额外花钱。**现在就是这一档，免注册反而是获客优势**——别急着加账号。

### 档位 B：正式上线（几千用户，有账号有备份）

| 项 | 方案 | 月成本 |
| --- | --- | --- |
| 数据库 | Supabase Pro / Neon（Postgres + 自动备份） | $19~25 |
| 账号 | **Supabase Auth 或 Clerk**（免费档覆盖前 1 万 MAU） | $0~25 |
| 对象存储 | Cloudflare R2 存图（出口流量免费，这点很关键） | $2~10 |
| 托管 | Railway / Vercel | $20~40 |
| 监控 | Sentry 免费档 | $0 |
| AI | 视活跃度 | $100~500 |
| **合计** | | **约 $150~600/月（¥1000~4000）** |

**账号系统不要自己写。** 密码哈希、会话管理、找回流程、2FA、撞库防护、泄露应急——
这是最容易出事又最不该自己扛的部分。用托管认证，把安全责任交给专业方，
免费档就够几千用户，代码量比自己实现还少。

### 档位 C：Lovable 那种规模（几万用户 + SLA）

数据库 $100~300、计算 $100~500、存储与 CDN $50~200、认证 $100~500、
监控与日志 $50~200，**AI $2000~20000**——合计 **$2500~20000/月**，其中 AI 占大头。
到这一档就必须有订阅收入（Lovable 是 $20~25/人/月，正是因为 AI 成本高）。

### 中国大陆正式运营的一次性成本

- ICP 备案：免费，但要国内主体 + 国内服务器（当前用境外域名规避）
- 收费就需要**增值电信业务经营许可证**：代办约 ¥5000~20000
- UGC 平台的**内容审核**是硬性的：第三方审核 API 约 ¥1~3/千次，或自建 + 人工复审
- 规模上来后可能需要等保二级：¥3~8 万一次性 + 年度维护
- 若涉及虚拟道具付费，还会牵出网文/游戏相关资质——这也是当前"不收费"的原因之一

### 真正该优化的：AI 成本

按一次完整创作（多轮对话 + 生成配置 + 校验重试）约 5 万~20 万 tokens 估算：

- 便宜模型（DeepSeek 级）：**一款游戏约 $0.05~0.3**
- 前沿大模型：**一款游戏约 $1~5**（贵 10~30 倍）

三个杠杆，按性价比排序：

1. **分层用模型**：日常闲聊/改文案用便宜模型，只有生成整份配置、数值配平时才上大模型。
   平台已经是多供应商架构（`AI_PROVIDER`），做这件事只需要在 agent 里按任务选模型。
2. **缓存系统提示**：系统提示很长（工作室守则 + schema 说明），命中缓存能便宜约 10 倍。
3. **配额与付费墙**：配额已经有了（按编辑钥匙计日请求与 token）。要收费时它就是计费基础。

### 建议的路径

先别升级。等到出现下面任一信号再动：

- 作者开始抱怨"换了台电脑找不到我的作品"（→ 上账号，档位 B）
- 单日 AI 花费超过你愿意承担的额度（→ 先做分层模型与缓存，再谈收费）
- 有人开始拿平台传违规内容（→ 上内容审核，这条没得商量）

在那之前，把钱和时间花在"作者能不能做出好游戏"上，比花在基础设施上划算得多。
