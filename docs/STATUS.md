## 一句话

「字游 WordPlay」是一个**平台化的游戏制作 agent**：创作者只提想法，一支 AI 团队（主策 / 剧情 / 人设 / 数值）
按专业流程把它做成一款完整的网页文字游戏，发布后一条链接即玩、无需注册、零部署。

平台有**两种做法**，作者在 `/new` 选：

- **快速模式**（默认）：作品是一份配置，喂给平台的通用引擎渲染。上手快、有三级校验与
  600 局模拟兜底，代价是所有作品长得一样。
- **自由模式**：作品自带一套网页文件（HTML/CSS/JS），跑在平台的沙箱 iframe 里，
  界面与玩法结构全由 AI 按作者的要求写。适合「界面本身就是卖点」的作品。
  代价是平台的模拟器与三级校验帮不上忙——那套是给通用引擎用的。

平台的两条铁律（任何改动都不能违背）：

1. **所有游戏都必须能"用平台做出来"**，而不是靠人手写代码塞进去。官方示例也一样——它们全部由
   平台自己的 schema + 工作流产出，过同一套门槛。做不到这点的功能，等于平台没这个能力。
2. **固化的是工作流，不是游戏模板**。创意讨论 → 数值设计 → 机制设计 → 人设画像是固定的；
   页签、栏目、机制都由配置推导——没有赛程数据就没有赛程页。给所有游戏套同一个模板是重大错误。

## 线上

- 生产环境：Railway（Nixpacks，`npm run build` / `npm start`），域名 `word-game-platform-production.up.railway.app`
- 数据：SQLite 落在挂载卷 `/data`（`DATA_DIR=/data`），一个游戏 = 一行 JSON，发布只是标记公开，**不触发任何部署**
- 开发分支：`claude/text-game-platform-handoff-op7cmd`（仓库当前唯一分支，也是默认分支，所以没有 PR）
- 旗舰位：`FLAGSHIP_URL` 指向独立部署的 [Val Manager](https://github.com/WeijieCao77/Val_Manager)，
  首页旗舰卡片点进 `/flagship` **在站内 iframe 里直接玩**（服务端先探测对方是否允许嵌入，拒绝时降级为外链）

### 创作者侧（`/new` → `/edit/:id`）

- **AI 驻场工作室**：四职能署名发言（【主策】【剧情】【人设】【数值】），作者是老板——
  只出想法和方向，专业空白由团队补全；对话区顶部有阶段条（创意对齐 → 方案确认 → 搭建 → 调优）
  和职能徽章，随时知道"现在在哪一步、在跟谁说话"
- **新手引导**：第一次进工作台自动开的聚光灯教学（11 步，框出每个板块讲它是干嘛的），顶栏「引导」可重看
- **六个页签**：预览试玩（与玩家页同源）/ 设计卡 / 配置 / 校验 / 内容库 / 封面·素材
- **保存不丢**：对话记录、设计卡、配置全部存服务端；编辑钥匙存本机并支持钥匙串导出导入
- **内容库**：官方与其他作者共享的桥段按当前作品题材推荐排序，看中就装
- **封面与素材**：自定义封面 / 16 款官方主题封面预设 / 游戏内图片素材上传（可勾选共享到公共素材库），
  上传的图会自动同步进设计卡的「素材清单」
- **模块功能库（后台）**：14 个可选游戏功能模块登记在 `src/lib/schema/modules.ts`，
  **不在前台显性展示**——作者要就装，AI 觉得需要会主动建议

### 账号（游客与注册用户并存）

- **游客是一等公民**：不注册也能创作、发布、游玩，作品靠本机编辑钥匙认人（现状不变）
- **注册用户**：用户名 + 密码存在平台自己的库里——scrypt 加盐哈希，明文永不落库；
  会话是 httpOnly cookie，数据库只存 token 的 sha256 指纹（库被拖走也无法冒充登录）
- **认领**：注册/登录时自动把这台浏览器上的游客作品收进账号（只认领无主且钥匙对得上的），
  「我的创作」页也能随时手动认领一次
- **归属与编辑权**（这条是安全边界，改动前先想清楚）：
  - 作品**无主**时，编辑钥匙即身份（游客模式）
  - 作品**一旦收进账号**，钥匙就不再单独授权——只有登录且是归属人才能编辑，
    哪怕别人手里握着正确的编辑钥匙、哪怕是同一台浏览器换了个账号登录
  - 登录后创建的作品直接归账号、默认用账号名署名
  - 判断只有一处：`canEditGame`（`src/lib/session.ts`），新写接口一律用它
- **管理员**：平台的第一个注册账号自动成为管理员，`/admin` 凭账号角色进入，不再依赖环境变量。
  兜底通道：可选环境变量 `ADMIN_USERS`（逗号分隔用户名），其中的账号登录时自动提升为管理员
- **防撞库**：同一 IP 连续 8 次登录失败后冷却 15 分钟；用户名不存在与密码错误返回同一句提示

## 质量门槛（新内容上线前必须过）

1. `npm test` 全绿（当前 **417 passed / 2 skipped**，45 个测试文件）
2. `TEMPLATE=xxx.json npx vitest run tests/adhoc-template.test.ts`：**零错误零警告**、600 局模拟
   全结局可达全卡片触发、**开局即死率 0**
3. `npm run build` 通过、`npx tsc --noEmit` 零错误
4. 改了界面就用 Playwright 起本地服务截图验收（浏览器在 `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`）

三级校验是平台的护栏：zod 结构校验 → 语义校验（悬空引用/孤儿卡/不可达结局/行动点预算/联赛挂接）
→ 模拟校验（跑几百局用数据说话）。**AI 生成的配置必须过这三关才写库。**

**自由模式的护栏是另一套**（三级校验和模拟器都量不了作者自己写的代码），一共四层，
每一层都是被线上真实翻车逼出来的：

1. **一级语法**（`src/lib/syntax-check.ts`）：写文件当场编译一遍，语法错当场打回
2. **接线体检**（`src/lib/wiring.ts`）：文件写了却没被 index.html 引 / 引了不存在的文件
3. **缺失引用体检**（`src/lib/js-refs.ts`）：谁调了一个谁都没定义的名字
   （线上真死过一部：`registerSetup is not defined`，玩家点开只剩 64 个字）
4. **运行报错回传**（`play-diagnostics.ts` → `game-frame.ts` → `api/games/:id/errors`
   → `ai/runtime-errors.ts`）：作品在**真浏览器**里抛的异常，每轮自动贴进 AI 的
   【运行报错】。玩家页和作者预览走同一条路——以前预览那条是断的，
   于是 AI 对着「没有报错记录」宣布做好了

前三层是静态的（写文件时就说），第四层是动态的（真跑起来才知道）。
静态那三层的铁律是**宁可漏、不可冤**：误报会让 AI 去修一个不存在的 bug，一轮几十万 token。

语义校验里还有几层「看起来能玩、其实是假的」的体检，都是被真实翻车逼出来的：
- **内容体检**：只加不用的可见变量、没人赋值却被引用的变量、同卡里做的事完全一样的假选择
- **承诺体检**：简介写了「可以分配天赋点」却没有加点环节、吹了 N 种结局实际只有几个
- **文笔体检**（`src/lib/schema/prose.ts`）：AI 腔的机检——套话密度、每段升华、
  形容词轰炸、句子长得一样。只报警告，文风终究是作者的自由
- **模拟指标**：一字不差的重复段落占比、局均读好几遍却没变体的热卡、兜底结局占比

## 接手时要知道的坑

- **表达式绝不用 `eval`**：自研受限语言（`src/lib/expr`），有长度/深度/步数上限。加函数要走白名单。
- **随机必须可复现**：种子化 mulberry32 存在存档里，同种子同操作结果一致。
  引擎里任何地方都不要用 `Math.random()`（模拟器与测试都依赖这点）。
- **密钥永远不进代码和对话**：Railway Variables / GitHub Actions Secrets 里配置。
  `railway-vars` workflow 会拒绝设置 `*_API_KEY` / `*TOKEN*` / `*SECRET*` 这类变量名。
- **容器出口屏蔽了 railway.app 与 api.github.com**：Railway 操作走 GitHub Actions，GitHub 操作走 MCP 工具。
- **DeepSeek 的 `deepseek-chat` 已于 2026-07 下线**，默认模型改为 `deepseek-v4-flash`。
- **每完成一段就提交推送**：容器会回收，未推送的工作会丢。
- 微信内打开 Railway 域名容易被拦，内测期让用户复制链接到浏览器打开。

## 已知待确认（拆分引擎时发现，尚未处理）

这些都不是崩溃级问题，但接手的人应该知道它们存在。改动前先想清楚是不是有意为之：

1. **`endTurn` 的结算循环里，条件结局用的是外层作用域**，读不到该次结算的 `row` 与 `compute` 局部量
   （`src/lib/engine/settle.ts`）。想写「这场比赛净胜 20 分就触发结局」目前做不到。
2. **排序规则有两份拷贝**：`internal.ts` 里 `rank()` 内置函数与 `leagues.ts` 的 `leagueStandings`
   用的是同一套「胜场 → 净胜 → 名字」排序，改排名规则要改两处。
3. **`searchKeyword` 在游戏没配检索台时直接抛错**，而同类只读查询（`notebookItems` / `pendingInput` /
   `upcomingRows`）都是返回空值。调用方得自己先挡一道。
4. **`advanceSimTime` 的非周期分支用 `turn > maxCycles` 判超时**（没有 `turnsPerCycle` 时把 maxCycles
   当最大回合数用）。行为说得通，但字面读起来像单位错配。
5. 卡片文案与兜底结局的插值用的是**进入这张卡时的作用域**，不是效果结算之后的。
   多数情况看不出来，但作者若在同一张卡里「先加钱、再在文案里报余额」，报的是加之前的数。
