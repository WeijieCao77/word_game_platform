# 平台功能设计体检（2026-08-27）

> 老板的原话：「我们做的是平台，你先看看平台的功能设计有没有什么问题，先检测一下，
> 至于背后连接的模型不够强力的问题我们下一步再解决」。
>
> 所以这份**只查设计，不查模型**。每一条都按同一个格式写：
> **是什么 → 在哪几行 → 它让老板付了什么代价 → 怎么改**。
> 排序按「离验收标准有多远」，不按修起来有多容易。
>
> 判据是 `docs/PLATFORM.md` 那页纸和 `CLAUDE.md` 的验收标准，不是我的口味。

---

## 结论先写在前面

平台这半年补的是**建造能力**（写大文件、切文件、数据表、连续搭建、异步长轮次），
这半边现在是够用的——旗舰实测一次能长到 17 万字符、4 个文件、没有停滞也没被整份重写。

**缺的是另外半边：验收能力。**「做得出来」和「做出来的能玩」是两件事，
平台现在只管前一件。老板这两天的四次投诉——打不开、名字没地方填、一排点不了、
按键点了就卡——**全部落在验收这半边的空白里**，一个都不是模型笨的问题：
平台压根没在看这些东西，所以模型也看不到、改不了。

下面六条里，一到四条都是同一个根：**自由模式没有验收闭环。**

## 一、自由模式的发布**没有门槛**——校验的是一份根本不执行的配置 ✅ 已修（2026-08-27）

**是什么。** `src/app/api/games/[id]/publish/route.ts:27` 在发布前跑
`validateGameConfig(record.config)`。可是自由模式作品的 `config` 是新建时
用 `blankStory(title)` 生成的一份空白故事配置（`src/app/api/games/route.ts:57`），
它**不参与运行**——玩家跑的是 `files` 里的 html/css/js。
于是这道门槛永远是绿的：**文件一个字都没看过就放行。**

快速模式发布前要过三级校验 + 断头路检查，自由模式发布 = 直接翻牌。

**代价。** 老板那句「游戏库里新出现的 val manager 根本玩不了，显示出错。
是不是现在平台新做的游戏都有问题」——问题就在这里。那部作品开局就抛
`registerSetup is not defined`，而它一路发布进了公开游戏库，没有任何一道关拦它。
平台**有** `syntax-check`（第一级）和 `js-refs`（第二级接线体检）这两把尺子，
写文件时也确实在用，但**发布这道口子没接上去**。

**怎么改。** 发布自由模式作品时，把已有的三样合成一道发布体检：
① 每个 js 文件语法过；② 接线体检没有 `nowhere` / `not-loaded` 级的引用；
③ 无头开局跑一次 `/play/:id/`，2.5 秒内不抛异常、`#app` 有内容。
①②是纯静态的、现成的；③要新增（见第三条，同一个基建）。
判罚照快速模式的规矩：**error 拦住，warning 放行并明说**。

**已经这么做了**（`src/lib/publish-gate.ts`）。落地时跟原方案有一处不同：
第 ③ 层没有新写一个「无头开局」，而是**直接用平台自己那份试玩体检报告**
（`store.playCheckGet(id)`）——那套东西第三条已经做出来了，工作台和 AI 用的
也是同一份，没必要再搓第二把尺子（这一天已经吃过一次两把尺子打架的亏）。

配套的两条硬规矩：

- **没体检过一律拦住**，并且告诉作者去哪儿点。「没测到」不等于「没问题」。
- **体检比文件旧也拦住**——改完文件不重新体检就发，等于拿上一版的结论给这一版背书。

修的过程中还揪出一个一直在的假阳性：接线体检把平台自己的虚拟运行库
（`wgp.js` / `wgp.css`）当成缺失文件，于是**每一部新建的作品**都被报一句
「index.html 引用了 wgp.css，可作品里没有这个文件」。这条一直在误导 AI，
而门槛一接上去就会**把平台自己发的模板拦在发布之外**——端到端自测第一关撞出来的。

## 二、已经发布的作品，**没有办法发布新版本** ✅ 已修（2026-08-27）

**是什么。** 工作台顶栏只有一个开关（`src/app/edit/[id]/page.tsx:879`）：

```
{published ? "取消发布" : "发布"}
```

而 `publish/route.ts:42` 只在 `published === true` 时才 `versionPublish()` 打快照。
两条合起来是：**作品一旦发布，作者再改，就没有任何按钮能把改动推给玩家**——
因为那个按钮这时写着「取消发布」。

要上线只能：取消发布（`play/[id]/[...path]/route.ts:69` 当场对所有非作者返 403，
**链接立刻死掉**）→ 再点发布。中间有一段真空，而且没有任何地方提示要这么做。

更糟的是平台**知道**有落差却只告诉了 AI。`src/lib/publish-drift.ts` 把
「有 N 个文件改了还没发布」拼成一段话塞进 AI 的上下文（`agent.ts:484`），
末尾写着「**先请创作者点「发布」**」——可作者的界面上没有那个按钮。
`docs/HANDOFF-2026-08-26.md` 第六节第 2 条早就记着这个缺口，一直没补。

**代价。** 我自己这两天写 `scripts/fix-game.mjs` 时，每一轮修完都得手动
POST 一次 `{published:true}` 才能让玩家看到修的东西——因为界面上做不到。
真实创作者没有脚本，他会陷在「AI 说修好了，我点开还是坏的」里出不来。

**怎么改。** 把一个开关拆成三件事，因为它们本来就是三件事：

| 现在 | 应该是 |
| --- | --- |
| 发布 / 取消发布（一个开关管三件事） | **① 发布新版本**（打快照、推给玩家，随时可点，有落差时高亮 + 显示「N 个文件未发布」） |
| | **② 链接可达**（拿到链接就能玩，跟挂不挂公开库无关） |
| | **③ 公开挂牌**（在游戏库里列出来——撤下不该杀链接） |

后台 `/admin` 的「撤下」现在动的也是同一个 `published` 字段，
所以「把半成品撤下公开库」＝「把作者和测试者的链接一起弄死」，这不合理。

**已经这么做了。** 落地的样子：

- 存储加一列 `listed`（公开挂牌）；`published` 从此**只管链接可达**。
  老库升级时按 `published` 回填一次 `listed`，行为跟改之前一模一样。
- 公开库列表（首页、`/api/games`、后台）改看 `listed`。
- 发布接口收三件事：`publishVersion` / `linkOpen` / `listed`。
  老写法 `{ published: true|false }` 继续能用，语义是「三件一起做/一起收」——
  脚本和旧前端不用改。
- 门槛只在**让玩家多看见东西**的时候跑（发版本、开链接、挂公开库）；
  关掉任何一样都不用过——作者随时有权把自己的作品收回去。
- 工作台顶栏从一个开关变成三个：**发新版本**（有落差时高亮，显示「N 个文件没发」）、
  **链接：开/关**、**公开库：挂着/没挂**。
- 后台「撤下」只动挂牌。

`publish-drift.ts` 那句「先请创作者点『发布』」也终于说得通了——按钮现在真的存在。

## 三、平台看不见「点了没反应」——试玩体检只活在 CI 脚本里，不在平台里 ✅ 已修（2026-08-27）

**是什么。** 平台现在能看见的只有**抛出来的异常**：运行库在沙箱里抓 →
外壳 postMessage → `POST /api/games/:id/errors` → 进 AI 的【运行报错】。
这条链路是通的，也确实救过场。

但「玩不了」有一大半**一个异常都不抛**：

- 按钮绑了 `onclick` 却没有对应的处理函数（有些写法静默失败）
- 点了以后界面一个字都没变
- 导航上挂着 6 个页签，其中 4 个点了不切屏
- 标签写着「你的名字」，`label[for]` 指向一个不存在的 input（老板遇到的那个）

平台**有**能力发现这些——`scripts/screens-freemode.mjs`、`scripts/smoke-freemode.mjs`、
`scripts/fix-game.mjs` 里的 play-check 全在干这件事，还挺准。
**但它们跑在 GitHub runner 上，是我的工具，不是平台的能力。**
作者用不到，AI 也拿不到。这直接违反铁律 1：
「只能靠改平台代码/外部脚本实现的东西，等于平台没有这个能力」。

唯一进了平台的是最后那条——`src/lib/play-diagnostics.ts:126` 的开局体检
（查 `label[for]` 指空），2026-08-27 才补进去，而且只查这一种。

**代价。** 老板三次投诉（名字没地方填 / 一排点不了 / 按键点了就卡）全在这个盲区里。
`2ena8oju` 那部作品，AI 连修四轮九个版本还是卡在建角色第二步：
**它每一轮拿到的都是「没有报错记录」**，因为确实没有异常，只是点了没反应。
让一个瞎子修 bug，换多强的模型都没用——这也是为什么「先解决模型」的优先级要往后放。

**怎么改（这是老板已经批的那条路）。** 把 play-check 从脚本搬进平台，成为
和【运行报错】同一级的第三只眼：

1. `src/lib/playcheck/` —— 无头开局：走一遍开场流程，把导航一个个点过去，
   记「第几步走不下去 / 哪一屏没有可点元素 / 哪几项点了界面没变」
2. 每轮 AI 开工前自动跑一次，结果拼成【试玩体检】塞进上下文
   （格式照 `describeRuntimeErrors` 那样，没问题就一个字不占）
3. 工作台上给作者同一份结果（见第四条）
4. 发布时也用它（见第一条）

一处基建，四条都受益。

**已经做了**（commit「试玩体检进平台」）：`src/lib/playcheck/` 三件——
出口注入的浏览器端 `sweep.ts`（只在带 `?wgpcheck=1` 且有编辑权限时注入，
玩家绝不会被塞进一个自动点击器）、服务端的 `report.ts`（当外人的输入收，
翻译成给 AI 的话）、`/api/games/:id/playcheck` 加一张只留最新一份的表。
每轮 AI 干完工作台自动跑一次，结果进下一轮的【试玩体检】；守则里跟着写死
「没有【运行报错】≠ 没问题」。第四条的「体检」页签一并做了。

本地拿真浏览器验过：坏样例（标签指空 + 四项导航只有一项真切屏）查出
「下一步/返回 点了没反应」「导航 3/4 项点不动」「开局卡在第 2 步」；
好样例零误报。验的过程中还揪出自己两处报得不准的地方，当场改掉——
详见那条 commit。

## 四、自由模式的作者，**界面上一条体检结果都看不到** 🟠

**是什么。** `src/app/edit/[id]/page.tsx:926` 那份页签表里，「校验」页签只在
快速模式出现。自由模式的页签是：预览试玩 / 文件 / 设计卡 / 配置 / 封面·素材——
**没有任何一页是给作者看健康状况的**。

而平台其实攒着这些东西：运行报错（`store.errorList`）、接线体检结果、
发布落差（`describeDrift`）。它们**全部只发给 AI**，作者一样都看不见。

**代价。** 作者判断作品好没好的唯一手段，是自己点开预览、自己踩。
踩到了也说不出所以然，只能跟 AI 说「还是玩不了」——正是老板这两天在做的事。
平台把创作者降级成了人肉冒烟测试机。

**怎么改。** 自由模式补一个「体检」页签，把已有的三样摆出来即可，
不需要新算法：最近的运行报错 N 条（带时间、文件、行号）、接线体检、
发布落差（「有 3 个文件改了还没发布 → 发布新版本」直接给按钮），
再加第三条做出来的试玩体检。

## 五、额度和验收标准自相矛盾：旗舰要 733 万，注册创作者一共给 200 万 🟠

**是什么。** 额度规矩（`PLATFORM.md` 第四节，老板拍板）：
游客 40 万/天（`src/lib/ai/quota.ts:46`）、注册账号 **200 万总量**
（`src/lib/store/sqlite.ts:57`，`AI_USER_GRANT`）、管理员不限量。

而平台自己搭 VAL MANAGER 量级作品的实测消耗是 **733 万 token**
（`HANDOFF-2026-08-26.md` 第三节，12 轮 / 17 万字符，那还只是半成品）。

**200 万 ≈ 旗舰体量的 27%。** 也就是说，按现在的规矩，
一个注册创作者**不可能**在平台上做出验收标准要求的那种作品——额度会先烧完。

`sqlite.ts:49` 的注释自己写着「从零做完一款能发布的游戏大概 20~100 万，
够做两三款」——那是**快速模式**的量。自由模式的大作品差了一个数量级，
而 `PLATFORM.md` 又写着「想做大作品的深度创作者 = 真正的用户，平台的核心能力为他们而建」。
这两句话现在打架。

**这不是要涨价**（现在不收费也不为收费做建设，这条我没碰）。
是这条线得有个明确说法，三选一由老板定：
① 深度创作者走申请/管理员放行；② 200 万是「起步额度」，作品有实际进展再续；
③ 认下来——快速模式的作品用 200 万足够，自由模式的大作品暂时只有内部做得起。
三条都行，但不能像现在这样：规矩和标准各说各的，等创作者撞上去才发现。

## 六、自由模式的**数值**没有任何护栏 🟠

**是什么。** 快速模式有 600 局模拟：全结局可达、全卡片触发、开局即死率 0。
自由模式**一局都不跑**——平台对作品的数值一无所知。

老板原话：「这个游戏全是问题，不仅是功能，还有数值」。

**为什么难。** 自由模式的数值全在 AI 写的 js 里，平台没有形式化的模型可以模拟，
这跟快速模式不是一个难度。所以这条我不打算在这一轮解决，先记在这里，
免得它被「功能修好了」的成绩掩盖过去。

**能先做的一小步**（不用理解游戏也能做）：无头跑一局机器人（随便点 50 步），
记数值曲线，只报三种明显毛病——数值溢出/NaN、点了 20 步什么都不变（死水）、
三步之内必死（开局即死）。这三样跟具体玩法无关，是通用的。

## 已经做对的，别在改的时候弄坏

顺手记一笔，免得后面有人「优化」掉：

- **草稿 / 线上快照分离**（`game_versions` + `live_version`）：AI 写坏一轮，玩家不会当场玩到坏的。这个设计是对的，第二条要改的是它的**界面**，不是它本身
- **报错回收不要编辑钥匙**（`errors/route.ts` 的注释写了理由）：最有价值的错正是玩家踩出来的
- **发布落差主动告诉 AI**（`publish-drift.ts`）：省下过三轮八十万 token 的空转
- **两条路带进度互切**：对方轨道的目录一直摆在上下文里，「照着翻译不要重编」
- **/new 先选路再选起点**：自由模式不再是 11 个模板里的第 4 行
