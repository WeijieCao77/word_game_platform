## 一、你那个「我为什么改不了」，是我上一个改动的 bug

截图上那句「⚠ 这部作品还有一轮在跑」不是你操作错了，是平台把你锁死了。

AI 那一轮跑在服务端进程里。我合 PR 触发部署 → 容器重启 → 那一轮当场死了，
可数据库里那行还写着「running」，而解锁条件是「静默 30 分钟」。
于是你发一句顶回来一句，那一轮永远不会有结果。

已修，四处：

| 改动 | 治什么 |
| --- | --- |
| **开机清扫** | 启动那刻还 running 的必然是上一条命留下的尸体，直接判死。重启即解锁，不用等 |
| **心跳** | 跑着的那一轮每 20 秒盖一次戳，判死从 30 分钟收到 3 分钟 |
| **409 带任务号** | 不再把你顶回来，而是接上去看那一轮的结果，跑完提示你把刚才那句再发一次 |
| **放弃这一轮** | 等超过 30 秒，转圈旁边出现出口，点了立刻放开 |

## 二、为什么做出来的游戏和 VAL MANAGER 差距这么大

先摆数字，不辩解。

| | 原版 VAL MANAGER | 平台最好的一次（e2e 第 6 次跑） |
| --- | --- | --- |
| 体量 | **13,132 行** | 171,573 字符 / 4 个文件 ≈ **4,500 行** |
| 主界面 | 26 个专属界面 | **11 / 11**（说明书里列的那 11 个全有） |
| 弹层与专属组件 | —— | 9 / 12（缺赛前布置、战术滑条、合同条款） |
| 花了多少 | —— | 12 轮 / 733 万 token |

**形状是对的，量只到三分之一。** 你截图那一屏（选队界面、分赛区、队标与强度）
其实正是原作的开场——问题是往里点几层就见底。

差距分三层，按分量排：

### 第一层：提示里有一句假话，让 AI 每轮故意只干一点点 ← 昨晚修了

`prompt.ts` 里写着「一轮对话有时间上限（**默认 40 秒**）」。那是同步时代的数字，
异步化之后自由模式一轮实际有 **12 分钟**。AI 照着那句话把活切成一小口一小口，
每轮加一小块就停下来问「要继续吗」。

- 预算改成如实告诉它，并明说「把预算用满，一轮里可以连着调十几次工具」
- 工具轮次上限 16 → 40。**该管住一轮的是时间，不是次数**——16 次在 12 分钟
  用满之前就被数完，那个闸门形同虚设

### 第二层：AI 不知道「还差什么」 ← 昨晚补了

e2e 流水线能跑出 11/11 界面，是因为它拿着 `spec.md`（体验说明书）分十几轮驱动它。
工作台里没有这个东西：你说一句，它做一点，它自己没有清单也没有验收，
所以每轮都在「交个底」而不是「补第 7 项」。

建造日志里加了**可打勾的剩余清单**：你描述的规模当场拆成条目，每轮先挑没打勾的做，
做完打勾；**清单没清空就不许问「还要加什么」**。

### 第三层：没跑够——这是算术 ← 昨晚做了「连续搭建」

12 轮到 4,500 行。要到 13,132 行，得 35 轮上下、2000 万 token 量级。
而你在工作台里一句句催，一次坐下最多几轮——**没有任何一次交互式会话跑过 12 轮**。

所以做了**连续搭建**：点一次，服务端一轮接一轮地跑，每轮之间替你说
「接着做，照剩余清单往下搭，不要问我要不要继续」。

- 工作台上是「连续搭建」按钮 + 轮数选择（5/10/15/20）
- 跑在后台，关页面也不中断；进度实时显示「第 3/10 轮 · 正在写 screens-squad.js…」
- 三个出口：轮数跑满 / 你按「放弃这一轮」/ 额度不够，后两个都会说清停在第几轮、为什么

## 三、顺带修的：实测量的一直是「另一条路」

复刻实测原来用**同步** POST 干等回信——那条路一轮只有 180 秒预算，
而且最重的那一轮必然被网关掐成 502。也就是说**之前所有的增长曲线，
量的都不是你在工作台里实际走的那条路**。

现在改成拿任务号 + 轮询，跟工作台同一条路（单轮 12 分钟），
并在脚本化的十步之后加一段连续搭建，单独报这一段涨了多少。

## 三点五、睡前那两条：手机端玩不了 / 收录之后手机上看不到

### 手机端玩不了 —— 两处硬伤，都是量出来的

**1. 作品少了 viewport 那一行，整部作品在手机上就废了（主因）**

自由模式作品的 index.html 一旦没有

    <meta name="viewport" content="width=device-width, initial-scale=1">

手机浏览器就按**桌面宽度排版再整体缩小**。实测量过同一份 HTML：
**没这行是 980px 排版，有这行是 390px**。字小得看不清、按钮点不准——
玩家的感受就是「这游戏手机上玩不了」，**而且不报任何错**。

平台的起手骨架本来有这一行，但 AI 用 `write_file` 重写 index.html 时很容易丢掉。
修在**服务端出口**（跟兜底诊断同一条路）：没有就补上，作品自己写了就不动它。
**不改作品的任何文件，所有已经存在的作品立刻受益。**

**2. 整个网站在手机上能横着拖**

390px 宽的屏幕上顶栏的「＋ 开始创作」被推到 431px，整页可以横向拖动——
而首页恰恰是所有人进来看到的第一屏。窄屏改成允许换行 + 一道 `overflow-x:hidden` 兜底。
另外 `100vh` 在手机上量的是「地址栏收起时」的高度，游戏底部那排按钮被压在地址栏
底下点不着，四处全改成 `dvh`。

**线上核对（2026-08-26 17:59，线上跑的是 `4913740`）**：用真浏览器按
320 / 390 / 430 三个宽度打开首页 / 我的创作 / 新建 / 登录 / 两个玩家页，
**18 项全过**——没有一页能横着拖，每一页都有 viewport。

### 收录之后换手机看不到 —— 是「只能靠人记得点」

先说排除掉的，两条都是线上量出来的、不是推测：

- Railway 上 `/data` 挂着 5GB 持久卷、`DATA_DIR=/data`——**数据不会被部署冲掉**。
  线上体检当场核对：公开游戏库 13 部、测试账号名下 1 部（VAL MANAGER），都在。
- **单实例**：连问 8 次 `/api/health`，进程编号一直是同一个（`700129fe`）。
  所以不存在「电脑那次请求打到 A、手机那次打到 B」这种劈成两半的情况。本地照着老板的流程跑一次就过（建作品 → 注册 → 收录 →
换一套 cookie 重新登录 → 手机视口打开我的创作），那段逻辑本身是对的。

问题在流程里有个**只能靠人记得**的环节：收录按钮只在「我的创作」页上有一个。
漏点一次，换设备就什么都找不回来，而且没有任何提示。

改成自动：**打开工作台就收**（作者真正待着的地方），打开「我的创作」也收一次。
安全性没放松——服务端只认领当前无主的作品，且必须出示正确的编辑钥匙。

顺带治了这一页的哑巴状态：原来账号那一路取失败是静悄悄吞掉的，
「账号名下 0 部」和「没取到」长得一模一样。现在登录后直接摆出
「账号名下 N 部 · 本机钥匙 M 部」。

实测走通全程：游客建作品 → 注册 → **不点任何按钮**只打开工作台 →
换一个全新的手机上下文登录 → 我的创作里看得到那部作品。

## 四、实测结果

跑了两次。第二次（run 5）是干净的——没有部署去撞它——数字是今晚最好的一组。

| | 之前最好的一次 | run 4（被我的部署撞死） | **run 5（干净的一次）** |
| --- | --- | --- | --- |
| 代码量 | 171,573 字符 · 4 个文件 | 145,137 · 9 个文件 | **242,951 字符 · 9 个文件**（约 7,000 行） |
| 主界面 | 11 / 11 | 11 / 11 | **11 / 11** |
| 弹层与专属组件 | 9 / 12 | 8 / 12 | **11 / 12**（只缺战术滑条） |
| 真实数据表 | 三张全用上 | 三张全用上 | **三张全用上** |
| token | 733 万 | 395 万 | 2,513 万 |

文件构成：`game.js` 79,283 / `style.css` 33,383 / `transfer.js` 33,316 /
`match.js` 23,985 / `career.js` 20,412 / `business.js` 18,388 /
`tournament.js` 17,880 / `relations.js` 15,514 / `index.html` 790。

**原作是 13,132 行，这次做到约 7,000 行——过半了。** 而且是分了 9 个文件、
按模块拆开写的，不是一坨。「能不能一层层搭到几千行」这一关，答案已经很清楚：能。

### 但玩家还是打不开——而且这次查出的原因，比作品本身的 bug 重要得多

冒烟检查（以玩家身份、不带钥匙去玩）：

    ✓ 开场有 198 个字符　✓ 可点元素 1 个　✓ 点击能推进　✓ 手机视口不横向溢出
    ✗ 控制台报错: [WGP] 画界面 ng2 出错： TypeError: Cannot read properties of undefined (reading 'rep')

开局向导第 2 屏（出身三选一）渲染时崩了，于是流程走不下去，
「找不到导航、只有一屏」是同一个毛病的连锁反应。

**然后是今晚最值得记的一段。** 回炉修了三轮，每一轮报错**一模一样**：

- 第 1 轮：AI 定位到根因（`originById(undefined).rep`），打了三处补丁 → 报错没变
- 第 2 轮：AI 又修了四处，还顺手改了存档续玩 → 报错没变
- 第 3 轮：AI 判定「**这是旧版本留下的记录**，报错行号 118:64 跟当前文件对不上」，
  逐条审计了 game.js 全部 5 处 `.rep` 读取点，结论是「查完确认没有可修的东西」，
  **不改了**

它的观察是对的（行号确实对不上），推论是错的。**不是记录旧，是玩家在跑的那份代码旧。**

平台的规矩是「作者看草稿，玩家看最近一次发布的快照」。实测只在开跑时发布过一次，
之后三轮补丁全落在草稿上——每一轮玩的都是同一份**冻住的**旧代码，
所以报错一个字都不会变。三轮、约八十万 token，全花在跟一个不可能变的版本较劲。

这不是 AI 笨，是**平台没把这件事告诉它**。已经补两处：

1. **实测 harness**：回炉每一轮改完，重新发布再玩（一行）。
2. **平台**（`src/lib/publish-drift.ts`）：草稿和线上快照一有出入，
   就在 AI 每一轮的上下文里明写「有 N 个文件改了还没发布，玩家看到的仍是旧版本」，
   并点破那句最容易误判的话——**「修完还是同一个报错、行号还对不上」不是记录过期，
   是他们根本没在跑你刚写的代码**。

### 顺带：接线体检（run 4 逼出来的那条）

run 4 的作品是 9 个文件 14.5 万字符、11 个主界面全在，玩家打开却只有 64 个字符的空白——
`index.html` 少了一行 `<script src="screens-setup.js">`。每个文件单独看语法都对，
所以第一级校验（逐文件编译）一路放行。

已补 `src/lib/wiring.ts`：每次写完文件当场对一遍 index.html，报两件事——
**有文件没人加载**（孤儿）、**引了不存在的文件**（断链）。只报告不拦截，
因为「先写文件、下一步再接进去」是正常节奏。run 5 没再犯这个错。

### 三个数摆在一起看

- **产量**：过半了（7,000 / 13,132 行），11/11 主界面、11/12 弹层，真实数据全用上
- **能不能跑起来**：还没过。已知一个开局崩溃；修没修好，因为上面那个坑，这次没测出来
- **成本**：2,513 万 token 一次。这个数必须往下压，不然「跑够三十轮」在经济上不成立

## 六、凌晨补的一段（老板半夜追问引出来的）

老板半夜连着问了三件事，串起来是同一根断线：

> 「他让我在预览里玩一把，但是预览里玩不了根本」（截图：血红的 `(kids || []).forEach is not a function`）
> 「游戏库里又有两个 val manager，哪个才是能玩的？」
> 「新出现的 val manager 根本玩不了，显示出错。是不是现在平台新做的游戏都有问题？」

### 先回答问题（有据可查）

新加了一条 `游戏库现场分诊` 流水线：用真浏览器把线上**每一部**已发布作品打开、
点一下主按钮，报能不能玩。全库 13 部：

| 结论 | 作品 | 证据 |
| --- | --- | --- |
| ✓ 能玩 | `dlezoceb`「VAL MANAGER」 | 首屏 2618 字（队伍列表带赛区/级别/强度），点随机抽签进俱乐部界面，16 条导航、行动点 4/4、预算 647,439、首发五人 |
| ✗ 开局即死 | `2ena8oju`「VAL MANAGER」（test1，8/26 17:42） | `registerSetup is not defined（game.js:308:3）`，正文只剩 64 字 |
| ✓ | 其余 11 部（含官方示例 9 部） | 正常 |

所以**不是「新做的都有问题」**，13 部里死的只有这一部。但它死的方式是平台的锅。

### 断线在哪

1. **作者预览里的报错，服务端根本收不到。** 玩家页（`CodeGameFrame`）会接沙箱发出来的
   `wgp:error` 并存进 `game_errors`；**编辑器的预览页签一个字都没接**。
   于是：作者看到血红横幅 → 服务端一无所知 → AI 调 `read_errors` 得到「没有报错记录」
   → 坦然宣布做好了 → 下一轮接着往上盖。作者看到的「AI 说做好了、我这儿一片血红」
   就是这么来的。顺带发现预览连 `wgp:load` 都没人回，开局要读档的作品在预览里一直转圈。
2. **`registerSetup is not defined` 是加载顺序错了**，不是没写：

       index.html：… game.js, screens-setup.js …   ← game.js 排在前面
       game.js:308        registerSetup();          ← 启动时就调
       screens-setup.js:5 function registerSetup(){ ← 定义在后面那个文件里

   语法对、文件都引了、名字也确实定义过——可执行到那一行时后面那个文件还没加载。
   平台原有的三层护栏查的都是「定义在不在」，没有一层查「调的那一刻在不在」。

### 补了什么

- `src/components/game-frame.ts`：外壳协议抽成钩子，**玩家页与编辑器预览共用同一份**。
  作者预览到的环境 = 玩家玩到的环境。预览存档另开一个键，试玩不冲掉正式那一局。
- `src/lib/ai/runtime-errors.ts`：有报错就自动贴进 AI 每一轮的【运行报错】，
  不再指望它主动调 `read_errors`。分「这一版抛的」和「上一版留下的」，
  拿不到写文件时间就一条都不算（宁可漏，不可冤）。
- 连续搭建**先修再搭**：上一轮把作品写炸了，下一轮说的是「先别往下搭」。
  以前最贵的失败是在一个打不开的作品上再加十几轮页面。
- 编辑器里当场弹「这一版打不开：<报错>」，带**「让 AI 去修」**按钮——原文直接发过去。
- `src/lib/js-refs.ts`：第二、三层静态护栏——「调了一个谁都没定义的名字」
  与「**调的时候那个文件还没加载**」。判据只认加载那一刻会执行的代码
  （顶层语句、顶层 if/for/try、立即执行函数、被它们调到的顶层函数一路传递），
  回调和对象方法一律不算——「点击时才调另一个文件的渲染函数」是正常写法，报了就是误报。
- 守则加硬规矩：**启动代码一律挂在 `window.addEventListener("load", …)` 里**，
  这样谁前谁后都不影响。

自由模式现在有四层护栏（前三层静态、第四层动态），写在 `docs/STATUS.md` 里。
