# 平台的定位（一页纸，新想法先过这里）

> 2026-08-26 与老板逐条对齐的结论。**所有新想法、新功能、新改动，先拿这页纸过一遍**；
> 过不了就别做，觉得这页纸本身错了就先找老板改这页纸，别绕过它。
> 散在其他文档里的判断与本页冲突时，以本页为准。

---

## 一、平台是干什么的（目的）

「字游 WordPlay」是一个**平台化的游戏制作 agent**：创作者只提想法，一支 AI 团队
（主策/剧情/人设/数值）把它做成一款完整的网页文字游戏，发布后一条链接即玩、无需注册、零部署。

平台的能力尺子只有一把：**平台的 AI 能不能做出 VAL MANAGER 量级的完整体验**
（量的是玩家体验不是代码；深度和丰富度一分不能少；必须由平台 AI 做出来，人一行游戏代码都不许写）。
详见 `CLAUDE.md` 的「验收标准」。

## 二、服务对象（老板拍板：两个都要，角色不同)

| 对象 | 用什么 | 对平台的意义 |
| --- | --- | --- |
| **想快速做个小游戏的普通人** | 快速模式 | **拉访客的**。不怎么吃资源，是流量入口和注册钩子 |
| **想做大作品的深度创作者** | 自由模式 | **真正的用户**。平台的核心能力为他们而建 |

资源分配照此执行：快速模式保证「上手快、有护栏、不翻车」即可，不追求无限做深；
平台的攻坚投入（建造能力、验收闭环、界面表达力）押在自由模式上。

## 三、两条路的关系（并行 + 可切换）

- **长期并行**，谁也不吃掉谁：快速模式是「聊完就能玩」（配置 + 通用引擎 + 三级校验 +
  600 局模拟护栏），自由模式是「界面自己定」（AI 写整套网页，跑在沙箱里）。
- **必须能切换，而且切换要能带走大致进度**（老板原话）。现状与差距：
  - 快速 → 自由：已有闸门（AI 必须先讲清代价、创作者点头才能带 `switchToCode` 切），
    但切过去等于推倒重来——只有设计卡和聊天记录还在，卡片与数值全部作废。
  - 自由 → 快速：完全没有。
  - **要立项的能力**：切换时至少把设计卡、数据表（`data/*.csv`）、题材与人设设定带过去，
    能翻译的内容尽量翻译（卡片文案 → 页面文案，或反向）。进了 `ROADMAP.md` 下一批候选。

## 四、商业（现在不收费，也不为收费做建设）

- **未来会收费**；现在不收费，也**不讨论、不预建**收费相关的东西（付费墙、订阅、计费页）。
- 现在唯一的闸门是额度，规矩定死：**游客 40 万 token/天、注册账号 200 万总量、管理员不限量**。
  额度同时是未来计费的地基，但仅此而已。
- **对外放量前内容审核没得商量**——这堵墙在放量那天之前必须砌好，现在（邀请制内测、
  境外域名、不收费）可以缓。

## 五、能力边界（平台做什么、不做什么）

**平台提供的是能力，不是某一款游戏的需求。** 判断一个新想法该不该做，照这四问
（出处 `ROADMAP.md`，与本页同效）：

1. 它是**平台能力**还是某个游戏的需求？后者不做。
2. 作者能不能**只靠对话**用起来？要读 schema 才会用的功能等于没做。
3. 它是**可选模块**吗？「每个游戏都必须有」的东西要非常谨慎。
4. 快速模式的能力过得了三级校验和 600 局模拟吗？过不了就不是完整能力。
   （自由模式的对应门槛是冒烟检查 + 界面体检。）

**明确不做**（有变化找老板改本页）：

- 不把 Val Manager 手搬进平台——它是旗舰内容与流量锚点，平台要的是「别人用工作台也能做出这个量级」
- 不给所有游戏套统一模板；页签、栏目、机制一律由配置推导
- 不做音乐/音效设计岗（定位是大量文字 + 少量图片）
- 不手写游戏代码塞进平台当示例——官方示例必须由平台自己的工作流产出
- 素材不从网上爬图——版权不干净的东西不进平台，封面样式一律原创（SVG 优先）
- 引擎不用 `Math.random()`，表达式不用 `eval`，密钥不进代码不进对话

## 六、铁律（与 `CLAUDE.md` 相同，抄在这里是为了这页纸自足）

1. **所有游戏都必须能「用平台做出来」**。只能靠改平台代码实现的游戏功能，等于平台没这个能力。
2. **固化的是工作流，不是游戏模板**。创意讨论 → 数值设计 → 机制设计 → 人设画像固定；
   产出全部由配置推导。
